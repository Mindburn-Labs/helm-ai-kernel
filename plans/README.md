## Historical target outcome (not current state)

`helm-ai-kernel` was intended to feel as guided and polished as a modern
agent CLI while remaining a deterministic governance tool:

1. Running `helm-ai-kernel` in a terminal presents a compact, branded chooser
   for the next safe action.
2. `helm-ai-kernel setup` detects the environment, explains each step, asks
   only necessary questions, applies changes transactionally, verifies the
   integration, and ends with one exact next command.
3. Every command and subcommand has side-effect-free `-h`/`--help`, grouped
   discoverability, suggestions, and shell completion.
4. Human output has a coherent HELM visual language; non-TTY, `NO_COLOR`,
   `TERM=dumb`, and JSON output remain plain, stable, and accessible.
5. Destructive actions never execute from help, preview, typo, missing
   authority, or ambiguous target input.
6. A future authorized release would need binaries, docs, package-manager
   installs, integrations, and source-owned production evidence to agree on
   v0.8.0; this planning record is not that evidence.

## Findings considered and rejected

- **Replace the CLI with Cobra or another framework:** rejected. The existing
  registry, Go `flag`, and `core/internal/cli/ui` are sufficient; a framework
  migration would add risk without fixing the lifecycle model.
- **Make every command a full-screen TUI:** rejected. Interactive rendering is
  reserved for setup, explicit watch surfaces, and approval pickers. Ordinary
  commands keep scrollback, copy/paste, and pipeline semantics.
- **Copy the screenshots with a large logo on every invocation:** rejected.
  Show a compact wordmark once during an interactive first run; repeated output
  prioritizes state, evidence, and next action.
- **Add usage telemetry to prove UX quality:** rejected for v0.8.0. The CLI can
  be qualified with deterministic journey tests and opt-in user research; no
  new data collection is required.
- **Add a self-updater:** rejected. Homebrew and signed release artifacts remain
  the update paths until an updater has a separately approved trust model.
- **Keep producing the `helm` executable alias:** rejected as the canonical
  experience because it collides with Kubernetes Helm. Plan 005 provides a
  deprecation window rather than silently deleting compatibility.
